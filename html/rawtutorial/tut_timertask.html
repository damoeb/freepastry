Timer

Scheduling tasks on the FreePastry timer.

Download the tutorial files: DistTutorial.java, MyApp.java into a directory called rice/tutorial/timer/.

This tutorial will show you how to schedule a task on the FreePastry thread. To be compatible with the commonAPI, the approach is to schedule a message to be sent to yourself at a regular interval.

Let's start with the changes to MyApp.

First a simple message. 

  /**
   * NOTE: It is unsafe to send this message to
   * anyone but the localnode.
   *
   * The reason:
   * It is a plain Message, not a RawMessage: it has
   * no serialize(OutputBuffer) and no type, so it
   * cannot go over the wire.  Endpoint.route() only
   * accepts RawMessages; scheduleMessage() delivers
   * it locally without serializing it.
   */
  static class MessageToSelf implements Message {
    public int getPriority() {
      return MAX_PRIORITY;
    }
  }

MessageToSelf is a plain Message, not a RawMessage. This is fine for what we are going to use it for, because scheduleMessage() delivers it to the local node without serializing it. You cannot send it to another node: it has no type and no serialize(OutputBuffer), and Endpoint.route() only accepts RawMessages. The messages that MyApp does send to other nodes are the raw MyMsgs from Lesson 3.

Here is the change to the constructor of MyApp, where we schedule the MessageToSelf. The first parameter is the Message that will be sent to MyApp. The second is the delay (in millis) until it is first sent. The third parameter is the period at which the message should be repeated. 

    endpoint.register();

    // Send MessageToSelf every 5 seconds, starting in 3 seconds
    messageToSelfTask = endpoint.scheduleMessage(new MessageToSelf(), 3000, 5000);

As you can see, we have asked FreePastry to deliver the MessageToSelf in 3 seconds, and then continue to deliver it again every 5 seconds. Note that there is also a version of scheduleMessage() that doesn't take the 3rd parameter, and therefore doesn't repeat.

We stored the task as a member variable so that we can cancel it later. 

  /**
   * This is the task sends the MessageToSelf every 5
   * seconds.  We keep it as a member variable to
   * cancel later.
   */
  CancellableTask messageToSelfTask;

Whenever we receive the MessageToSelf we are just going to print out the current time. We read the time from the environment's TimeSource rather than from System.currentTimeMillis(), so that the code also works on the simulator's virtual clock. In your application you could call a method to do periodic maintenance, send messages to other nodes etc. 

  public void deliver(Id id, Message message) {
    System.out.println(this+" received "+message);
    if (message instanceof MessageToSelf) {
      // This will get called every 5 seconds, on Pastry's thread.
      // Thus now we can assume we are on Pastry's thread.
      // This is where your application does its periodic work, e.g. send messages or print its status.
      System.out.println("I got the MessageToSelf at time:"+environment.getTimeSource().currentTimeMillis());
    }
  }

Finally, we make a public method to cancel the task. 

  /**
   * Call this to cancel the task.
   */
  public void cancelTask() {
    messageToSelfTask.cancel();
  }

The DistTutorial.java is based on lesson3, but we removed the code that routes messages and sends to the leafset. For this example it is unnecessary to launch multiple pastry nodes, so we will only launch one. We added a bit of code after the node is ready to cancel the task after 15 seconds. 

    System.out.println("Finished creating new node "+node);

    // wait 15 seconds
    env.getTimeSource().sleep(15000);

    // cancel the task
    app.cancelTask();
